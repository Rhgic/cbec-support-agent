跨境电商多语种智能客服 Agent 系统

面向东南亚 / 欧美市场的客服工单自动化：多 Agent 协作走完 「脱敏 → 分类 → 检索 → 工具调用 → 生成 → 风险闸门」全链路闭环， 以风险护栏与成本可控为核心——能自动答的自动答，涉及钱与承诺的坚决转人工。

这个系统解决的三个真实痛点

多语种

客户多语种，知识库中文

东南亚 / 欧美客户用英、西、印尼语提问，而政策知识库是中文。

跨语种向量检索（BGE-m3），知识库只存中文，不做多语种冗余。
幻觉 = 资损

答错政策要真赔钱

错答退换货 / 乱承诺退款，直接赔付，还拉低平台绩效（如 Amazon ODR）导致店铺降权。

检索置信度不足即短路拒答，无依据不进生成——宁可拒答，不让模型编。
成本敏感

大规模工单，逐条调模型会被刷爆

客服是大规模场景，每单都走 LLM，成本不可控。

规则前置的两层管线，高频请求零成本命中，只把候选交给模型。

核心设计决策 · 面试深挖点

01
知识库仅存中文，跨语种检索替代多语种冗余
业务驱动选型 + 合规硬约束，不是炫技
›

N 语种 × M 篇政策的冗余维护必然腐烂，任一政策变更要全语种同步。改用 BGE-m3 的跨语种对齐能力，查询与文档同模型、无需翻译。

更硬的理由：客户工单含 PII，不出境是合规要求（GDPR），所以 embedding 本地部署、单次检索成本为 0。

02
检索分数不足直接短路拒答
幻觉 = 资损，宁可拒答不编造
›

Top-1 相似度低于阈值即短路，不进生成、转人工。电商客服的幻觉是真实赔付 + 店铺绩效损失。

阈值 0.45 由实测曲线标定（见指标区），不是拍脑袋。

03
风险闸门：定义「哪些坚决不自动」
高风险动作仅起草，强制人工
›

涉及退款 / 赔付 / 承诺 / 金额的回复，Agent 只能起草，必须人工确认才发出。别人比「能自动多少」，本项目定义「哪些绝不自动」。

规则层六条确定性规则命中即 high，可审计；LLM 只在规则未命中时判 low / mid。

04
不对称降级策略
成本护栏 fail-open，风险闸门 fail-close
›

成本护栏（限流 / 配额 / 熔断）故障 → 放行并告警；风险闸门故障 → 默认拦截转人工。

因为代价不对称：护栏失效只是多花钱，风控失效是不可逆的资损。「一律 fail-open 或 fail-close 都是没想清楚」。

05
规则前置的两层管线
零成本筛高频请求，控制 LLM 调用成本
›

分类与风险都是「规则先筛 → 命不中才调 LLM」。高频模式零成本命中，长尾才付费给模型。

「规则前置省下 X% 的 LLM 调用」就是可量化的成本数字。

业务价值 · 这对老板意味着什么

省人力

每 +10% 自动解决率 ≈ 少 1–2 名客服

按客服月薪 6–8k、单人产能估算，约 8–20 万/年。多语种 7×24 排班本就难招，自动化价值在旺季放大。

依据：拒答率 7.7%（真实问题极少误拒）+ 规则前置 34% 免调 LLM。自动解决率已端到端实测 28%（n=100）。人力折算仍为估算 · 须接真实工单与真实规模复核
保权重

护住 ODR < 1%，避免 listing 被压

AI 乱答售后 → 买家开纠纷/差评 → ODR 上升 → 平台限流甚至封 listing。旺季一次断掉主力 SKU 现金流，损失可达几十万级。

依据：高风险拦截召回 100% + 对抗集无依据回答 0%。这是「避免损失」，比「节省」对老板更痛。
控成本

大规模工单，LLM 成本可控且防刷爆

规则前置 34% 免调 LLM + 结果缓存 + 全局熔断，防止大促当天被刷穿；退款/赔付绝不自动，堵住羊毛党套 AI 退款。

依据：单均成本按 DeepSeek 公开价估算。估算 · 量级待压测

以上为按标注假设的业务价值估算，非已实现收益——用于说明这套系统对生意意味着什么。 真实数字需接入真实工单与规模后测算。把技术指标翻译成「省人力 / 保权重 / 控成本」，是这份作品面向业务的一层。

项目边界与已知短板

  • PII 脱敏仅覆盖结构化字段（邮箱 / 电话 / 单号）。小语种人名、地址正则召回有限，需 NER 模型，当前范围未做——明确记为短板，不声称已覆盖。
  • 订单数据为 mock。但运单号真实、物流查询真实、知识库与政策文本为真实来源——只有身份与订单虚构。
  • 检索阈值基于种子数据集标定（0.45）。方法与曲线可复现，扩充数据集后需重跑 sweep 复核再定稿。
